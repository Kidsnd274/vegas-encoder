## The plan in brief

- **One product core, two consumers.** A portable C++17 core turns a recipe plus the
  media VEGAS delivers into FFmpeg arguments. The exporter DLL links it for rendering.
  The Flutter app calls the same code through `dart:ffi` for the live preview, so what
  you see is what renders.
- **Guided and Command modes edit one recipe.**
  - Guided configures video and audio separately: encoder, rate-control mode,
    quality or bitrate, speed, profile, bit depth, every parsed FFmpeg option, and
    extra arguments.
  - Command lets you write the whole FFmpeg command. Vegas Encoder owns only
    `{inputs}` (the VEGAS pipes) and `{output}`.
  - Switching between modes keeps both.
- **The popup is a separate window, not Flutter inside VEGAS.**
  - The DLL's small native page launches `VegasEncoder.exe --edit-session`, owned and
    modal over VEGAS's dialog.
  - Settings travel through crash-safe session files.
  - The template keeps a complete snapshot of the settings.
- **FFmpeg is user-supplied and qualified on this PC.**
  - The app finds installations (PATH, winget, Scoop, Chocolatey, manual) and
    identifies them by content hash.
  - It parses encoder options from `-h encoder=X` and test-encodes every hardware
    encoder, because "listed" isn't "works".
  - Container rules come from a measured matrix.
- **Presets** live as one file per preset, with revisions. Templates record their origin,
  so "Update from library" can show exact differences.

D1 fits your two main asks best: video and audio are set up separately, and the command you'd type in advanced mode is the same thing the controls edit. D5 is the pick if you'd rather it look native to Windows.

**How the questions you raised are answered:**
- **Which FFmpeg and which codecs:**
  - The app finds FFmpeg installs (PATH, winget, Scoop, Chocolatey, or one you browse to) and you pick a default.
  - It reads each encoder's options from FFmpeg itself, and test-encodes one frame with each hardware encoder, because NVENC/QSV/AMF are listed even when they won't work on your PC.
  - Container rules come from 226 real test files made with FFmpeg 8.1.3.
- **Normal and advanced modes:**
  - "Guided" has separate video and audio settings (encoder, quality or bitrate depending on mode, speed, profile, bit depth), plus every FFmpeg option and a free-text extra-arguments box per stream.
  - "Command" is the whole FFmpeg command. Vegas Encoder only owns the VEGAS input pipes and the output file.
  - Switching keeps both. I named them "Guided" and "Command" instead of basic/advanced; that's your call.
- **The VEGAS popup:** a small native page inside VEGAS's Customize Template dialog opens the Flutter app as a separate window on top of VEGAS. If that window crashes, VEGAS is unaffected. Templates keep a full copy of the settings, so they still render if you edit or delete the preset they came from.
- **Performance:** one C++ core turns settings into the FFmpeg command for both the VEGAS plug-in and the Flutter app, so the preview is exactly what renders. Start-up and editing time targets are written down, but still have to be measured on Windows.
